1. Contexte & Objectif

Le Service de Sécurité Incendie (SSI) de la Ville de Laval gérait les données de matières dangereuses dans des fichiers manuels. En situation d'urgence, la recherche d'information était lente et peu fiable.

Solution développée : une SPA (Single Page Application) React permettant aux dispatchers et chefs de caserne d'identifier en quelques secondes les bâtiments contenant des matières dangereuses dans un rayon de 500 mètres autour d'un point d'intervention, via une carte interactive Leaflet/OpenStreetMap.

Flux de données
Chargement : batiments.json → dataLoader.js (import statique synchrone) → App.jsx (variable module-level, jamais re-chargée)

Recherche : SearchBar → App.handleLocaliser() → geoEngine.geocoderAdresseSuggestions() (Nominatim) → setPointIntervention()

Filtrage : pointIntervention → geoEngine.filtrerParRayon() (haversine) → useMemo batimentsDansRayon → useMemo batimentsFiltres (niveau + type)

Affichage : batimentsFiltres → MapView (CircleMarker Leaflet) → clic marker → BuildingSheet (modale)
Composants internes de MapView

RecenterMap

Utilise useMap() pour appeler map.setView() dès que pointIntervention change. Repositionne la carte automatiquement au zoom 15.

ClickHandler

Utilise useMapEvents() pour capturer les clics sur la carte. Ignore les clics sur les markers SVG (path, circle). Implémente le fallback DEC-007.

TileErrorWatcher

Écoute l'événement tileerror de Leaflet. Affiche la bannière MESSAGES.FOND_CARTE_INDISPONIBLE si une tuile ne se charge pas. Nettoyage propre au unmount.

geoEngine.js — C-002, C-003
Fonction exportéeRôle
geocoderAdresseSuggestions(adresse)Retourne jusqu'à 3 suggestions Nominatim {lat, lon, libelle}. Timeout AbortController PARAM_005. Filtre Canada (countrycodes: 'ca').
geocoderAdresse(adresse)Retourne un seul résultat {lat, lon} (limit:1). Utilisé en fallback direct.
calculerDistance(lat1, lon1, lat2, lon2)Formule haversine — distance en mètres entre deux points GPS. Rayon Terre = 6 371 000 m.
filtrerParRayon(batiments, lat, lon)Filtre les bâtiments dans PARAM_001 (500m). Exclut silencieusement les bâtiments sans GPS (RA-009). Enrichit chaque résultat avec distance. Trie par distance croissante.
Politique Nominatim : Header User-Agent: PompiersLavalCartographie/0.1 (intranet-ssi-laval) + Accept-Language: fr obligatoires sur toutes les requêtes — conforme à la politique d'usage Nominatim/OSM.

10. Ordre de Réalisation (Chronologie)
  • Étape 1 — Analyse du dossier fonctionnel
    Lecture et analyse complète du dossier fonctionnel SSI Laval v1.0. Identification des 5 capacités, 10 décisions, règles transversales, paramètres système et messages utilisateur. Détection des lacunes (stack, tests, déploiement).
  • Étape 2 — Validation de la stack technique
    Proposition et validation : React 18 + Vite 5 + react-leaflet 4 + Vitest + CSS Modules + Nominatim. Aucune modification demandée par l'utilisateur.
  • Étape 3 — Génération manuelle du projet
    Node.js absent du PATH initial → npm create vite impossible. Tous les fichiers du projet générés manuellement : package.json, vite.config.js, index.html, .gitignore.
  • Étape 4 — Configuration centralisée (params.js)
    Création de src/config/params.js avec PARAM_001–005, MESSAGES (MSG-001 à MSG-007), et NIVEAUX_DANGER. Règle absolue : aucune valeur hardcodée dans les composants.
  • Étape 5 — C-001 : DataLoader
    Module dataLoader.js avec import statique JSON. Copie de donnees_etablissements.json vers src/data/batiments.json. Composant StatusBar.
  • Étape 6 — C-002/C-003 : GeoEngine + MapView
    Fonctions geocoderAdresse() et calculerDistance() (haversine) + filtrerParRayon(). Composant MapView avec RecenterMap, ClickHandler, cercle 500m, markers colorés.
  • Étape 7 — C-004 : FilterPanel
    Toggles niveau de danger (couleurs depuis params) + liste déroulante type d'établissement généré dynamiquement depuis le JSON. Filtres actifs par défaut (RA-010).
  • Étape 8 — C-005 : BuildingSheet
    Modale fiche synthétique 7 champs. Règle RA-013 (une seule fiche), RA-014 (champ vide), fermeture touche Échap, clic hors modale. Badge danger coloré depuis params.
  • Étape 9 — App.jsx : orchestration
    Câblage de tous les composants. États : pointIntervention, filtresNiveau, filtreType, batimentSelectionne, suggestions. Deux useMemo : batimentsDansRayon et batimentsFiltres.
  • Étape 10 — Tests unitaires (geoEngine.test.js)
    10 tests Vitest sur les deux fonctions pures : calculerDistance (3 tests) et filtrerParRayon (7 tests). Validation npm run test → 10/10 ✓.
  • Étape 11 — Build de validation
    npm run build → 88 modules compilés, 0 erreur. Dossier dist/ prêt pour déploiement intranet.
  • Étape 12 — Correctif CA-005 (suggestions Nominatim)
    Ajout de geocoderAdresseSuggestions() (limit:3) dans geoEngine. SearchBar.jsx : liste <ul> cliquable sous le champ. App.jsx : gestion setSuggestions + handleSelectionnerSuggestion.
  • Étape 13 — Correctif MSG-006 (TileErrorWatcher)
    Composant interne TileErrorWatcher dans MapView.jsx. Écoute map.on('tileerror'). Bannière orange MESSAGES.FOND_CARTE_INDISPONIBLE.
  • Étape 14 — Conformité Nominatim (User-Agent)
    Ajout de la constante NOMINATIM_HEADERS partagée avec User-Agent et Accept-Language: fr. Appliquée sur les deux fonctions de géocodage.
  • Étape 15 — Recalibrage coordonnées GPS
    Diagnostic : coordonnées fictives hors zone Nominatim → aucun bâtiment visible après géocodage. Recalage de +0.0029 lat / −0.0062 lon sur les 34 bâtiments. Zone validée : Chomedey, Laval. Adresse test : 3030 boul Le Carrefour.
  • Étape 16 — Versionnement Git & push develop
    Dépôt GitHub : hhamadou/Pompiers-laval-cartographie. Branche : develop. Dernier commit : 2b85c98 — scénario de test mis à jour et poussé.
