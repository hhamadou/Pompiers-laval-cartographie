🔵 Catégorie 1 — Fonctionnalités ajoutées (absentes du DF)
Ajout
Autocomplétion pendant la frappe (debounce 300ms)

Le champ d'adresse déclenche automatiquement une recherche Nominatim après 300ms d'inactivité dès 4 caractères saisis, sans que l'utilisateur appuie sur "Localiser". Le debounce est implémenté via useEffect + useRef dans SearchBar.jsx.

DF v1.0 : Le DF ne mentionne que le déclenchement explicite par clic sur "Localiser" (section 9 C-002, composant réf. 2 : "Au clic : déclenche géocodage"). L'autocomplétion live n'est ni demandée ni évoquée.
Ajout
Bouton ✕ Effacer / Réinitialiser

Un bouton ✕ apparaît dans le champ de saisie dès qu'il y a du texte. Au clic, il efface le champ et remet l'intégralité de l'état App à zéro : point d'intervention, markers, fiche ouverte, suggestions, messages d'erreur.

DF v1.0 : Aucune mention d'un bouton de réinitialisation dans les sections 2, 6, 9 (C-002, C-004), ou 17. Le DF ne décrit pas de mécanisme de remise à zéro. La section 9 C-004 mentionne que "les filtres persistent tant que l'utilisateur ne les réinitialise pas" sans préciser comment.
Ajout
Marker actif visuellement distingué quand une fiche est ouverte

Quand la fiche synthétique d'un bâtiment est ouverte, son marker sur la carte change d'apparence : rayon agrandi (14 vs 10), anneau blanc épais (weight 4), et l'étiquette de distance passe en fond sombre avec texte blanc. La prop batimentActifId est passée de App.jsx vers MapView.jsx.

DF v1.0 : La section 9 C-005 ne mentionne aucun changement visuel du marker lors de l'ouverture de la fiche. La règle RA-006 (section 9 C-002) impose uniquement que le marker d'intervention soit distinct des markers de bâtiments — pas de distinction entre marker actif et marker inactif.
🟣 Catégorie 2 — Comportements enrichis (DF présent, mais code va plus loin)
Enrichi
Fermeture de la fiche via touche Échap

La modale BuildingSheet.jsx écoute l'événement keydown sur le document et se ferme à la touche Échap. L'écouteur est nettoyé proprement au unmount.

DF v1.0 : CA-018 dit "Quand l'utilisateur clique ✕ ou sur un autre marker, alors la fiche se ferme". La touche Échap n'est pas mentionnée. L'exigence ENF-003 (accessibilité WCAG AA) justifie cet ajout sans le prescrire explicitement.
Enrichi
Fermeture de la fiche par clic sur l'overlay

Un clic sur le fond semi-transparent derrière la modale (l'overlay) ferme la fiche. Implémenté via onClick={(e) => { if (e.target === e.currentTarget) onFermer() }}.

DF v1.0 : CA-018 mentionne uniquement le bouton ✕ et le clic sur un autre marker. Le clic sur l'overlay est un ajout UX non prescrit.
Enrichi
Attributs ARIA complets sur tous les composants

Tous les composants incluent des attributs ARIA non prescrits dans le DF : role="dialog", aria-modal="true", role="alert", role="status", role="listbox", role="option", role="group", aria-pressed sur les toggles, aria-label sur tous les boutons et inputs.

DF v1.0 : ENF-003 demande "contraste élevé WCAG AA" et ENF-004 une "interface responsive tablette". Les attributs ARIA ne sont pas listés — ils dépassent le niveau de détail du DF.
Enrichi
Deuxième couche TileLayer (OSM France, opacity:0)

Une seconde couche TileLayer pointant vers tile.openstreetmap.fr/osmfr est ajoutée avec opacity: 0 comme couche de repli silencieuse. Le composant TileErrorWatcher détecte les erreurs de tuiles et déclenche MSG-006.

DF v1.0 : DEC-008 dit "Le fond de carte utilise les tuiles OpenStreetMap avec source secondaire en fallback" et la section 18.1 dit "Leaflet doit être configuré avec une source de tuiles secondaire dès le départ". Le DF prescrit le principe mais pas l'implémentation (opacity:0 + TileErrorWatcher sont des choix d'implémentation).

🔴 Catégorie 4 — Exigences du DF présentes mais non couvertes

Ces points sont dans le DF mais n'ont pas été implémentés ou vérifiés. À traiter avant validation finale.

Non couvert
ENF-004 — Interface responsive pour tablette

Le DF impose "Interface responsive — usage terrain chef de caserne". Le CSS actuel utilise un layout flex-direction: column de base, mais aucune media query ni test sur viewport tablette n'a été réalisé. L'interface n'a pas été validée sur résolution 768px ou 1024px.

DF v1.0 : ENF-004 — "Compatibilité tablette — Interface responsive — Usage terrain chef de caserne."
Non couvert
EF-009 — Taille de police minimale 14px dans la fiche synthétique

Le DF exige "La fiche doit être lisible sur tablette (taille de police minimale 14px, contraste WCAG AA)". La fiche utilise font-size: 0.85rem pour certains éléments secondaires (adresse, définitions), ce qui peut descendre sous 14px selon la taille de base du navigateur. Non vérifié formellement.

DF v1.0 : EF-009 — Exigence applicables à C-005 — "taille de police minimale 14px, contraste WCAG AA".
